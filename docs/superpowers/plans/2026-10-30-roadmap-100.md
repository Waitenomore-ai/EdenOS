# EdenOS Roadmap 100 Implementation Plan

Approved scope: the user's numbered 100-item list, followed by “do those 100
things”. Keep original numbers in docs/roadmap-100.md. Execute available work
inline; hardware-only checks stay blocked until evidence is available.

Architecture: retain Debian 13 amd64 live-build and GTK launcher. Add read-only
inspection and diagnostic tooling; no automatic disk changes. Keep the existing
artwork identity. Browser pilot stays unavailable until verification.

Constraints: 4 GB RAM, 32 GB storage, <=20 GiB installed and >=6 GiB free;
o telemetry or child cloud accounts. Never claim hardware results from unit
tests. Original design: docs/superpowers/specs/2026-10-30-eden-os-design.md.

1. Boot (items 1–20): add UEFI mode with copied disposable OVMF variables;
   fail on missing firmware; preserve BIOS mode. Test argument construction,
   tool errors and cleanup using controlled QEMU executables. Hardware items
   require the Intel iMac; no connected iMac is currently available.
2. Branding/version (21–30): stage reviewed artwork if transfer is available;
   otherwise record blocker. Embed version/build commit in image and show it
   in adult-help screen. Test invalid/missing metadata and literal values.
3. Launcher (31–70): fix repeated activity launches with one tracked subprocess,
   re-enable after exit, retain child-friendly error messages. Wrap navigation
   controls with FlowBox, scroll adult setup, improve focus and status handling.
   Test non-GTK logic locally; graphical checks require Debian GTK runtime.
4. Browser (81–90): disable unverified defaults and gate both wrapper and launcher
   on root-managed enablement AND reviewed status, in addition to Firefox policy.
   Test missing/malformed/disabled/unverified configs fail closed.
5. Measurement/recovery (91–100): add read-only hardware/version/storage report,
   exact 32 GB disposable VM guidance, update/backup procedures and release
   evidence checklist. Never partition the user's actual disks.
6. Run the full suite and shell syntax checks, request one focused review, push
   source with concurrency guard, and start a development build if inputs exist.

Pre-flight: source tests require boot-smoke, so new helper tests must stay in the
same checkout. The build embeds metadata before staging launcher assets. The
browser wrapper and launcher must consume the same gate to prevent disagreement.
